# TourManager – система управления маршрутами и экскурсиями

## Назначение
**TourManager** – веб-приложение для управления туристическими маршрутами, экскурсиями и учета участников.
Проект реализован на фреймворке Django с использованием реляционной базы данных (Django ORM), пользовательских форм и кастомной панели управления.

Приложение позволяет:
- просматривать список доступных маршрутов в браузере;
- просматривать подробную информацию о конкретном маршруте и связанных с ним экскурсиях;
- регистрироваться в системе с валидацией возраста (от 18 до 100 лет);
- входить в систему по уникальному идентификатору (ID) или под учетной записью администратора (`admin`);
- записываться на экскурсии с автоматической проверкой ограничений (возраст участника, свободные места в группе);
- создавать, редактировать и удалять маршруты и экскурсии через веб-интерфейс администратора;
- безопасно хранить данные между запусками приложения в базе данных.

## Используемые технологии
- **Python 3** – основной язык программирования;
- **Django 5.2** – веб-фреймворк;
- **HTML5** – разметка веб-страниц;
- **CSS / Bootstrap 5.3** – адаптивное оформление интерфейса;
- **SQLite / Django ORM** – работа с реляционной базой данных;
- **pytest** – автоматизированное тестирование;
- **flake8** – проверка качества кода (соответствие PEP 8).

## Целевая аудитория
Пользователи, желающие подбирать и бронировать экскурсии в соответствии со своими возрастными параметрами, а также администраторы туристического бюро, управляющие контентом системы.

## Предметная область
Основными объектами предметной области являются:
- **Пользователь (User / UserProfile)** – участник системы, имеющий имя, фамилию, уникальный `id` и возраст (`age`), а также флаг прав администратора (`is_staff`).
- **Маршрут (Route)** – туристическое направление, содержащее название, описание и протяженность в километрах.
- **Экскурсия (Excursion)** – мероприятие, привязанное к маршруту, со стоимостью, возрастными ограничениями (`min_age`, `max_age`) и лимитом участников (`max_persons`).
- **Группа (Group)** – объединение пользователей, записанных на конкретную экскурсию.

Один маршрут может содержать несколько экскурсий. Пользователь может записаться на экскурсию только при соблюдении возрастных критериев и наличии свободных мест.

## Страницы веб-интерфейса
- `/` – главная страница: приветствие, описание приложения и общая навигация (view-функция `index()`);
- `/register/` – страница регистрации новых пользователей с валидацией возраста (view-функция `register_view()`);
- `/login/` – страница входа по числовому ID или под учетной записью `admin` (view-функция `login_view()`);
- `/routes/` – список всех доступных маршрутов (view-функция `route_list()`);
- `/routes/<int:pk>/` – детальная страница маршрута и блок записи на экскурсии (view-функция `route_detail()`);
- `/admin-panel/` – кастомная панель управления для администратора (view-функция `admin_panel()`);
- `/admin-panel/route/add/` (и аналогичные пути для редактирования/удаления) – формы управления маршрутами и экскурсиями.

Если маршрут или экскурсия с указанным идентификатором не найдены, страница возвращает статус 404.

## Основные операции
- регистрация пользователя с проверкой возраста;
- авторизация по ID или роли администратора;
- просмотр списка маршрутов и детальной информации;
- проверка доступности экскурсии и запись пользователя в группу;
- защита от повторной записи и переполнения группы;
- CRUD-операции (создание, редактирование, удаление) для маршрутов и экскурсий через веб-интерфейс администратора.

## Хранение данных
Данные приложения хранятся в реляционной базе данных **SQLite** (`db.sqlite3`), управляемой через **Django ORM**.
Связи между пользователями, маршрутами и экскурсиями реализуются с помощью внешних ключей (`ForeignKey`, `OneToOneField`, `ManyToManyField`), обеспечивающих целостность данных.

## Назначение модулей
### `core/`
Пакет системных настроек проекта:
- `settings.py` – конфигурации базы данных, приложений и статики;
- `urls.py` – маршрутизация верхнего уровня.
### `main/`
Основное приложение системы:
- `models.py` – описание таблиц базы данных и логики валидации (`clean()`);
- `forms.py` – валидация пользовательского ввода (включая возраст 18–100 лет);
- `views.py` – обработка запросов, авторизация, проверка прав доступа и операции записи;
- `urls.py` – маршруты пользовательского интерфейса и панели администратора.
### `templates/main/`
Набор HTML-шаблонов, сверстанных с использованием фреймворка **Bootstrap 5.3**.

## Запуск приложения
Запуск веб-сервера разработки:
```bash
python manage.py runserver
```
После запуска откройте в браузере адрес:
```text
http://127.0.0.1:8000/
```

## Первичная настройка (Создание администратора)
1. Выполните миграции базы данных:
   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```
2. Создайте суперпользователя (администратора):
   ```bash
   python manage.py createsuperuser
   ```
   *(Укажите имя пользователя `admin` и задайте пароль).*
3. Теперь вы можете войти в систему через веб-интерфейс, введя на странице входа слово `admin`.
